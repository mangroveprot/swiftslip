pipeline as the other forms, and the employee signature is centred.

- **All five forms** ship a tokenized `public/<x>_template.docx`, tokenized once
  by `scripts/<x>-template-tokenize.mjs`, filled at runtime by
  `features/<x>/lib/word-export.ts`.
- **DTR's old path (gone):** built an HTML string, saved `.doc`. Replaced.
- **`src/shared/dtr-template.ts` is still the form WORDING** (title / column
  names / signature labels) but the export no longer reads it — the tokenized
  template carries the wording. It's kept in `downloadDtrWord`'s signature so

- **Template geometry:** TABLE#0 title, TABLE#1 identity (4 rows, value in c1 —
  note r0 has a borderless spacer in c2), TABLE#2 MONTH/YEAR (values in c1/c4),
  TABLE#3 daily grid (gridSpan rows; 16 rows → trimmed to header + 1 loop row).

- **Word COM is unreliable here** — `Documents.Open` returned "Sorry, we

  docxtemplater render + a Python zip/`document.xml` assertion instead.
  *(Correction, same day — the `make path` was the file being locked by an

- **"DTR template" in code means the form WORDING only** —
  `src/shared/dtr-template.ts` holds the title / column names / signature labels.
  It used to live in a `dtr_template` DB table (single row, id=1, editable in

## DTR Word export — 2-page → 1-page, name lands on the signature rule

**User feedback:** exported DTR came out as 2 pages, and the printed name was
missing from "Employee's Signature Over Printed Name".

**What I did:**

1. Diagnosed with Word COM: only the certifier caption paragraph
   (`p128 = "Signature Over Printed Name / Position"`) spilled to page 2. The
   name was missing because nothing in the template carries `{name}` — the
   preview shows it as an absolutely-positioned overlay, but the Word export
   had no analog.
2. **`scripts/dtr-template-tokenize.mjs`:**
   - New section **1b** — compact `TABLE#3` rows: `trHeight` 400 → 320,
     `tcMar` top/bottom 40 → 20.
   - Section **5** rewrite — the signature paragraph now carries the image,
     a `<w:br/>`, then `{name}` (image on top, name lands on the rule);
     `w:spacing w:after` reduced 400 → 40 so the name hugs the rule.
   - Sections **5c/5d** kept: drop the empty `<w:p/>` between "Certified by:"
     and `{certified_by}`, and tighten `w:spacing w:after="300"` → 0.
   - Section **5b** removed (its job is now done by the rewrite of 5).
3. **`src/features/records/lib/word-export.ts`** hardened for an empty
   signature: `getImage` falls back to a 1×1 transparent PNG, `getSize` to
   `[1, 1]`. (Earlier it would throw `Image not found` inside the image
   module.) `sigSize` is now explicitly typed `[number, number]`.
4. Headless harness re-built: `scripts/_dtr_export.mts` stubs `fetch`, `Image`,
   `document.createElement`, and patches `URL.createObjectURL` via
   `(URL as any).createObjectURL = ...` (don't replace `globalThis.URL`
   wholesale — Node's ESM loader uses `instanceof URL` and throws).
5. Verified via PowerShell COM: `$doc.ComputeStatistics(2)` → **1 page**;
   PyMuPDF render at 110 dpi confirms the layout — name sits directly on the
   signature rule, image above it; certifier name on its own rule below.

**Lessons / patterns worth keeping:**

- **Word COM works in this sandbox** as long as the file isn't locked by
  another Word process. With a fresh `C:\Temp\<name>.docx`, `Documents.Open`
  succeeds; previous "Sorry, we couldn't find your file" failures were
  caused by stale `WINWORD.exe` automation instances from prior probes.
  Clean those up by killing `Get-Process WINWORD | Where-Object { -not
  $_.MainWindowTitle }` — never touch a process with a real window title.
- **Don't replace `globalThis.URL`** in a tsx/Node harness — the ESM loader
  uses `instanceof URL` and `instanceof URL` becomes a non-callable proxy.
  Mutate `URL.createObjectURL`/`revokeObjectURL` directly instead.
- **`Range.Information(3)`** on `$doc.Paragraphs.Item(p).Range` gives the
  page number each paragraph landed on — that's how to find the exact spill
  point instead of trimming everything blindly. Same method works on table
  rows (`$tbl.Rows.Item(r).Range.Information(3)`).
- **The on-screen preview vs. the Word export must agree on the name's
  position**. `DtrPreview` already centered the printed name with an
  absolute overlay; the Word export must do the same, otherwise the user
  sees the preview one way and the exported `.docx` another. Put `{name}`
  in the same paragraph as the signature image (above the rule), not in
  the caption paragraph (which renders below the rule).
- **`docxtemplater-image-module-free`** requires valid PNG bytes from
  `getImage` — if `sigB64` is empty, pass a 1×1 transparent PNG; don't rely
  on the module skipping empty tags.
- **"1.07 bytes" account for the user's signature size**: `fitSignature`
  clamps to `150×45` px regardless of the source. Keep that constant in
  `src/lib/signature.ts` in sync with the inline `<w:ind>`/`w:spacing`
  budget in the template so the printed name still lands on the rule.
