## Crop dialog blank-until-drag + photo reuse hook

- BUG: `PhotoCropDialog` painted via `canvasRef.current` in a `useEffect`. Radix
  mounts DialogContent a commit after `open` flips, so the first run hit `null`
  and, with deps `[source, zoom, offset]` unchanged, never retried. Dragging
  changed offset -> re-ran -> picture appeared. That was the "need to click it
  to show the picture" report.
- FIX: hold the canvas in STATE via callback ref (`ref={setCanvas}`) and paint
  in `useLayoutEffect` keyed on `[canvas, source, zoom, offset]`. General lesson
  for this codebase: any effect that reads a ref inside a Radix portal must key
  on the element, not assume it exists on the first commit.
- NEW `features/profile/use-profile-photo.ts` -> `useProfilePhoto()`. One cached
  `["profile"]` entry; photo is a data URL in the row so there is no image
  request. Sidebar + AdminPanel use the hook; use it for any new surface.
