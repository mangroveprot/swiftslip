## LOA Word export defects (Word-rendered, verified)

- **What:** (1) the typed "Others" answer printed ON its fill line — the paragraph leading was `w:line="67" w:lineRule="auto"`, and under `lineRule="auto"` that attribute counts **240ths of a line**, so 67 ≈ 3.9pt for Calibri 11 (< a third of the text height) → Word overlapped the two lines. Raised to `w:line="190"` (≈10.9pt ≈ 14.6px between baselines). (2) `TRANSPARENT_PX` was RGBA(0,0,255,127) — a half-opaque **blue** — so every unsigned export drew a blue block in the signature cell; replaced with a true RGBA(0,0,0,0) pixel.
- **Verified end-to-end:** ran the real export module in Node (tsx harness, browser APIs stubbed) → Word COM → PDF → `PAGES=1` → rendered with PyMuPDF and visually confirmed. Temp harness/artifacts deleted.
- **Only file changed:** `src/features/leave-of-absence/lib/word-export.ts`.
- **Reusable technique:** `npx tsx` + stubbed `fetch`/`document`/`URL.createObjectURL` runs the real browser export headlessly; then PowerShell Word COM (`New-Object -ComObject Word.Application`, `ComputeStatistics(2)`, `ExportAsFixedFormat($pdf,17)`) gives a real page count, and PyMuPDF renders/crops the PDF for visual checks. Word IS installed at `C:\Program Files\Microsoft Office\root\Office16\WINWORD.EXE`.
- **Note:** `scripts/loa-template-tokenize.mjs` still carries the old blue `TRANSPARENT_PX`; it is only used for that script's own validation render, so it was left alone.
