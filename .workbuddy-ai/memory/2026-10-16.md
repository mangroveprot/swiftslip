# 2026-10-16

## OrgSelect emdash removed

- The Designation / Department / Position picker's blank "no value" option
  used `—` as a placeholder (was on the placeholder-exception list). User
  asked it gone — replaced with a single non-breaking space so the row is
  genuinely empty, and the closed control still shows the muted `text-sm`
  ghost text for the "nothing picked yet" cue.
- `src/components/common/OrgSelect.tsx` — two lines, the closed display
  and the blank `row("", …)` call.
- Updated `MEMORY.md` to drop the OrgSelect from the placeholder exception.
- `tsc --noEmit`, `eslint`, `prettier --write` all clean.
- ACTIVITY_LOG entry at top.
- **Later same day:** user reversed — `—` placeholder IS wanted on OrgSelect
  because an empty row in a list picker reads as a broken control. Restored
  both lines (closed display + blank `row("", …)`). The emdash belongs to
  the placeholder-exception list permanently now.

## Save profile dirty-state

- Save profile used to be always-active, so clicking it with no edits
  re-POSTed the row and flashed "Profile saved". User wanted it low-opacity
  like the Update password button.
- Added an `original` state mirroring `data` (set on load and on a
  successful save), an `isDirty` 7-field equality check, and
  `disabled={busy || !isDirty}` on the button. `.btn:disabled` already
  lowers opacity to 0.6.
- `src/features/profile/components/ProfileForm.tsx`.
- **Follow-up (same day):** first pass compared raw fields, so a Department
  round-trip that wiped and didn't restore the Position kept Save active.
  Switched to a derived `effectiveDesignation(p)` — only counts the
  position if it fits the chosen department — and stopped the department
  picker from destructively clearing `form.designation`. The Position
  picker's `value` now uses the derived value too, so the field still
  reads blank when incompatible (visible clearing preserved) but the
  underlying value survives a revert.

## Org lists now come from the DB on Profile too

- ProfileForm was hardcoded to the constants in `@/shared/org` for its
  Designation / Department / Position pickers. The admin screen reads
  `org_designations` / `org_departments` / `org_positions`, but a normal
  user on their own profile page saw the seed constants and never saw
  admin edits.
- Wired ProfileForm to `orgOptionsQueryOptions()` from
  `features/admin/queries`. Lifted the position-resolver helper into
  `@/shared/org` as `positionsUnder(department, lists)` so both screens
  resolve through one place. Constants in `org.ts` stay as the
  first-render / no-rows fallback.
- `src/shared/org.ts`, `src/features/profile/components/ProfileForm.tsx`,
  `src/features/admin/components/UserManagement.tsx`.
