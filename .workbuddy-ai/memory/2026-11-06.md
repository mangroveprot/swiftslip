### Status artwork → true 20px icons with a constant hairline
- Owner: "the wating hr is so thick make it thin, and also make it smaller the
  icons like this" + real dark queue screenshot. 4× zoom measurement: clipboard
  ~16.5×21px, briefcase ~19×17px, ~1.4px ink. Our 36px art was ~2× too big and
  the clipboard stroke rendered 2.04px vs the briefcase's 1.2px.
- **Root cause worth remembering:** stroke widths were in *viewBox user units*,
  but the viewBoxes are 60 and 180 units wide → same unit value renders at 3×
  different on-screen weight, and resizing silently re-thins/re-thickens.
- Fix: `StatusIllustration.tsx` now has module-local `STROKE_PX = 1.35` +
  `artStyle(size, viewW, viewH)` setting inline
  `--si-stroke = STROKE_PX * viewW / size`. Both icons hold a 1.35px outline at
  ANY size. Type: `CSSProperties & { "--si-stroke": number }`. React emits
  custom properties WITHOUT a px suffix (SVG needs a plain number).
- Deleted the `.si-wfhr`/`.si-onob` `--si-stroke` rules from `styles.css`;
  `stroke-width: var(--si-stroke, 2)` keeps a fallback for raw SVG markup.
- `HrQueueTable.tsx`: `STATUS_ICON_SIZE = 20`; default component size 20 (was
  64). `gap-2` + `pl-4` → label at ~44px, matching the reference. `w-48` kept.
- Verified visually with headless Chrome screenshot of the preview HTML
  (`--headless=new --screenshot --virtual-time-budget`); zoomed queue section
  matches the owner's screenshot. typecheck + lint clean (0 errors, same 6
  pre-existing ui/* react-refresh warnings).
- Convention: when the owner asks for "thin", tune the **on-screen px** via
  `STROKE_PX`, never the per-viewBox unit value.
