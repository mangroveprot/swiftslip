# 2026-11-07 — SSE auto-update feature + optimization

## What was built

Added lightweight automatic updates so HR sees employee-submitted OB forms and
employees see HR status changes without manual refresh. Free-tier safe.

### Architecture
- One SSE endpoint: `GET /api/updates/stream` (authenticated, per-tab).
- `UpdatesService` holds in-memory subscriber set; `publish({signal, audience?})`
  pushes to connected clients.
- In-process writes publish instantly via `ActivityLogService.logBy()` — zero
  DB reads on the primary signal path.
- Backstop poll every 60s (was 10s) using head-only probe: `select('id', { count:
  'exact', head: true }).gt('created_at', lastKnownTimestamp)`. Zero response
  body, just Content-Range header. ~1,440 reads/day (was 8,640).
- `ActivityLogService.logBy()` calls `UpdatesService.publish()` after DB commit.
- Client `LiveUpdates` component opens EventSource with `withCredentials`,
  invalidates mounted TanStack Query keys with version-gate + 5s throttle floor.

### Key files
- **API new module:** `api/src/apps/updates/` (controller, routes, service, repo)
- **API wiring:** express.ts (compression bypass for SSE, CSP), rate-limiter.ts

  `_headers` (CSP update)
- **Shared:** `shared/src/activity.ts` + activity-log types — added
  `ob.supervisor_approved` action

### Optimization pass (after user feedback)
Researched Supabase free tier (Nano: 60 connections, 250 IOPS, 500MB) and
Render free (sleeps after 15min). Applied:
1. Poll 10s → 60s (83% fewer DB reads)
2. Head-only probe (`head: true`) — zero response body
3. Timestamp watermark instead of row-id comparison
4. Stale-connection cleanup (drop after 3 missed heartbeats = 90s)
5. Client version-gate (skip duplicate/out-of-order signals)
6. Client 5s throttle floor (max 1 refetch wave per 5s)

### Free-tier constraints verified from docs
- Supabase Nano: 60 DB connections, 200 pooler clients, 250 IOPS, 500MB
- Render free: sleeps after 15min inactivity, 30-60s cold boot
- No Postgres LISTEN/NOTIFY, no Supabase Realtime, no per-row polling
- Rate limiter excluded for stream path (prevents reconnect death-spiral)

## Waiting-for-HR / resubmit status card restructure (owner's reference)

Owner's rule for this card: **"still use my icons and style just change the
structured"** — `StatusBadge`, `ProfileAvatar`, `FieldValue`, `FieldNote`,
card border/shadow and the HR label-left rail must not be restyled.

- Old rejection facts (`Rejected before`, `Their reason`, `Rejected before by`,
  `Reason then`, the "N days after the rejection" note, and the "was rejected"
  second-review sentence) are removed from `case "submitted"`. Reviewer,
  rejection date and HR's reason appear **only in `case "rejected"`**.
- Employee resubmit card = 4 columns: `Resubmitted` (amber),
  `You changed` (+ `Was: empty` / `Was: <old value>` derived from
  `resubmit_history[].changes[].from`), `Submission` (`ordinal(resubmits + 1)`
  + `Sent back N times`), `Waiting for` (`waiting(doc.submitted_at)`).
  No `full: true` on any of them — that flag breaks the 4-column grid.
- `ObStatusLine` no longer prints the amber "Resubmitted Nov 7, 2026" tail
  and suppresses `card.summary` for resubmits; header is just badge + avatar /
  name + id. A resubmit's date lives in the card's first column only.
- Edited-after-approval description: "You edited this form after HR approved
  it. HR will review it again." (reference copy). Rejection-resubmit keeps
  "You resubmitted this form. HR will review it again."
- Files: `web/src/features/official-business/lib/status-card.ts` (removed
  `reviewerPerson` and `afterRejection`, added `previousValue`),
  `components/ObStatusCard.tsx`. API reviewer decoration stays on the response
  for the historical record; only its comments were corrected.
- Verification: typecheck + lint pass (0 errors, 6 pre-existing warnings).
  `tsx` probe of `buildStatusCard` printed the reference's 4 columns verbatim
  and confirmed `Reason from HR` still carries the stored reason on rejected.
