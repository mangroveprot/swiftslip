# 2026-11-13

## Security review: are "crucial" API endpoints (create account) safe while publicly exposed?

Read-only audit; no code changes made.

- **Verdict: exposure is fine, authorization is enforced.** `POST /api/users` (create account)
  lives in `api/src/apps/users/routes/user.routes.ts`, which starts with
  `router.use(authenticate, authorizeAdmin)` — applies to every route in that router.
  There is **no self-registration endpoint** anywhere; no `auth.admin.createUser` / `signUp`.
  Only 2 of 25 route modules lack a router-level `authenticate`: `auth.routes.ts`
  (sign-in / sign-out / session public by design; change-password has route-level guard)
  and `attachment.routes.ts` (mounted behind already-authenticated form routers).
  Root `default.ts` exposes only `/health`, `/health/db`, `/health/inventory-db`, `/favicon.ico`.
- **Live probes** (`https://regasco.dpdns.org`): `GET /api/users`, `GET /api/admin/stats`,
  `POST /api/users` (empty body, no cookie) all → `401 UNAUTHORIZED`.
  `GET /api/auth/session` → `200 {"success":true}`. Evil `Origin` gets no `ACAO`.
- **Session cookie**: HMAC-SHA256 signed, httpOnly, Secure in prod, SameSite=Lax, 12h,
  re-validated against `users` on every request, password-hash fingerprint kills other
  devices. Global rate limit 300/15min per IP; sign-in throttle 10/ID + 20/IP per 15 min,
  250 ms failure delay, failed attempts logged.
- **Real issue 1 — deployed `CORS_ORIGIN` is the placeholder.**
  Live CSP shows `connect-src ... https://YOUR-SERVICE.onrender.com`; probing `Origin`
  confirms only that placeholder gets `Access-Control-Allow-Origin`. The site's own origin
  `https://regasco.dpdns.org` is NOT in the allowlist (works anyway because same-origin
  needs no CORS). `render.yaml` correctly says `https://regasco.dpdns.org`, but `api/.env`
  / root `.env` still hold the placeholder. Not currently exploitable (SameSite=Lax blocks
  cross-site cookie sends) but it is a claimable Render subdomain and a broken config.
- **Real issue 2 — no `Cache-Control: no-store` on API JSON** (confirmed on `/api/auth/session`).
- **Default seeded admin check (read-only Supabase REST):** 10 accounts total, **0** still use
  `admin123` / `staff123`; no `Administrator` / `Staff` seeded rows. So `SECURITY_AUDIT.md`
  finding C-1 is effectively remediated in the DB. **2 accounts still have bare legacy
  SHA-256 hashes** (`2026-639`, `2026-302`) — they re-hash on next successful sign-in.
- Other minor: `/health/inventory-db` publicly reveals `configured: true`; 4-char minimum
  password per product decision.
