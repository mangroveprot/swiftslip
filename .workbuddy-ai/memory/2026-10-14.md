## Emdash sweep across all user-facing copy

**User request:** remove/change the emdashes in the project — they make the copy
look AI-written. Started with one string (Activity logs description); the user
then said **"all of it, not only here in the logs"**. Do NOT remove emdashes
that are placeholders (e.g. the logo placeholders in form previews).

**What I did:**

1. Wrote a throwaway classifier (`C:\Temp\emdash_scan.py`) that walks `src/`
   and buckets each emdash as COMMENT / PLACEHOLDER / UI by tracking string
   literals and block-comment state. Baseline: **UI=77, PLACEHOLDER=18,
   COMMENT=530**. Essential — without it I'd be editing blind across ~110 files.
2. Applied an exact-match replacement map (`C:\Temp\emdash_fix.py`, then
   `emdash_fix2.py` for the AI system prompts) → **76 rewritten**. Final tally:
   **UI=0, PLACEHOLDER=18, COMMENT=527**.
3. Substitution rule used (keep consistent for future copy):
   - clarifying aside / restatement → **colon** (`"Full view: zoom…"`)
   - consequence → **`, so`** (`"already has 8 files, so remove one"`)
   - two independent clauses → **period** (`"No dates yet. Click Add date."`)
   - `X — full view` dialog titles → **`X (full view)`**
   - page-title separator (`lib/seo.ts`) → **` | `**
4. `ACTIVITY_LOG.md` entry at the top. Verified: `npm run typecheck` clean,
   `eslint` clean on all 30 touched files, `prettier --write` unchanged.

**Files touched (30):** all five editors (LOA/OB/COS/OT/DTR `RecordEditor`),
the four `XxxAssistantChat` greetings/hints, `AssistantChat`, `AiLauncher`,
`ActivityLogs`, `UserManagement`, `AssetRow`, `LocationFilterRow`,
`LoaFormFields`, `LoaOtherAttachmentsCard`, `OtOtherAttachmentsCard`,
`ObItineraryTable`, `CosScheduleTable`, `OtEntriesTable`, `SignaturePad`,
`lib/seo.ts`, `routes/rgc-asset-inventory.tsx`, and server toast strings in
`options.server.ts` / `auth.server.ts` / `access-codes.server.ts`, plus the
three `*-assistant.server.ts` system prompts.

**Lessons / patterns worth keeping:**

- **Emdashes are an AI tell in prose. This project's house style is now: no
  emdash in user-visible copy.** Substitute colon / comma / period instead.
- **Two exceptions, both intentional — do not "fix" these:**
  1. Lone `—` used as an empty-cell / missing-value placeholder in tables
     (`?? "—"`, `isBlank(x) ? "—" : x`). Standard data-table convention.
  2. The placeholder dashes in the form previews (`LoaPreview`, `ObPreview`,
     …) that stand in for the logo / typed values.
- **~522 emdashes remain inside code comments.** Those never render; the user
  explicitly chose (2026-10-14) to leave them. Don't sweep without asking.
- **Scan before editing.** For any repo-wide punctuation/word change, bucket
  occurrences into *comment* vs *code/string* vs *placeholder* first. A regex
  that just strips emdashes would have produced ~110 files of noise and hit the
  placeholders the user explicitly wanted kept.

### Correction — v1 of the scan under-reported (found 2026-10-14, same day)

My first classifier, `emdash_scan.py`, had a **block-comment state leak**: on a
line like `/** foo — bar */` it walked only up to the emdash, so it never saw
the closing `*/` and left `in_block=True` for **every following line in that
file** — silently bucketing later UI strings as "comment".

It missed **3 user-visible emdashes**, all fixed:

- `src/features/inventory/components/ViewAssetDrawer.tsx:407` —
  `"Asset type is required — tap the type to choose one."` → period.
- `src/routes/rgc-asset-inventory.index.tsx:10` —
  `pageTitle("Assets — RGC Inventory")` → `pageTitle("RGC Inventory Assets")`.
- `src/routes/rgc-asset-inventory.reports.tsx:10` —
  `pageTitle("Reports — RGC Inventory")` → `pageTitle("RGC Inventory Reports")`.
  (Rewrote rather than swapping in `|`, because `pageTitle` already appends
  ` | SwiftSlip` — two separators would read badly.)

**Lesson:** when writing a comment/string classifier, walk each line to its END
to maintain state; don't stop at the match. Always re-run the corrected scanner
and confirm the UI bucket is 0 before declaring a sweep done.

## Link-preview meta (og:image) + tagline + inventory titles

Same day, after the user shared a link and saw a placeholder image.

- **`APP.siteUrl` added to `src/config/app.ts`** = `https://regasco.dpdns.org`.
  Needed because `og:image` must be an **absolute** URL, and the route `head`
  renders during SSR before `window` exists — so `location.origin` is not

- **`src/lib/seo.ts`** exports `ogImage = \`${APP.siteUrl}${APP.logoPath}\`` and

- **Inventory route titles** are now uniformly `RGC Inventory <Section>` (Assets

- **Tagline** widened from "Daily time records, simplified." to **"Employee
  forms and time records, simplified."** — user's brief: cover the whole system
  (DTR + LOA/OB/COS/OT) **without enumerating every form**.
- **Caveat worth remembering:** `public/mindbridge_logo.png` is only **461×149**.
  Crawlers crop/letterbox anything far from 1200×630, so the preview will show

  image with the logo centred on a background — don't just upscale the logo.

**User preference confirmed:** wants broad, understated copy — don't emphasise

## Body gradient: cut the orange end (de-AI pass)

**User:** "this right bottom gradient… can we remove it? it looks vibe coded"
→ then, after I over-corrected: **"wait where my background? i said remove
those orange gradient dont remove everything"**.

**Read the complaint literally.** "Remove the orange gradient" means remove the
ORANGE, not remove the gradient. I deleted `--app-gradient` entirely and
flattened the body; the user wanted the wash kept with only the peach/salmon
end cut. Reverted the same day.

- **Final state of `--app-gradient`** (`src/styles.css`), kept and still `fixed`:
  `135deg, oklch(0.9 0.06 175) 0%, oklch(0.94 0.03 120) 35%,
  oklch(0.96 0.02 85) 65%, oklch(0.968 0.008 85) 100%` — mint → pale green →
  cream → warm paper. **Hue 45 (peach) and hue 35 (salmon) are gone**; that
  orange corner was the actual complaint. Do not reinstate them.
- **`--glass` is now opaque** (`oklch(1 0 0)`, was `oklch(1 0 0 / 62%)`). Its
  only purpose was letting the gradient through — with a flat body it would
  just read as grey.
- **Three glass surfaces updated** — dropped the dead `backdrop-blur-xl`, and
  `border-white/40` → `border-border` (white-on-white was invisible once the
  panel went opaque): `sidebar-ui.tsx`, `AppShell.tsx`, `AdminPanel.tsx`.
- The only `backdrop-blur` left in the app is `PreviewLightbox` over a dark
  image overlay — legitimate, leave it.

**Design lesson (house style now):** the multi-hue pastel rainbow behind every
screen was the strongest "AI-generated UI" tell in this app. **One hue, flat.**
If depth is wanted later, use a single-hue value shift (~2 stops, very low
chroma), never a multi-hue gradient, and never `fixed` full-bleed.

**Also:** inventory (`/rgc-asset-inventory`) has its own scoped styles and was
deliberately NOT touched — don't sweep design tokens into it.

## LOA export: long REASONS no longer spills to page 2

**User:** "this loa is doing a 2 pages if the reason is too long… the top has
too much spaces… we need to optimize this".

Three fixes, all in `src/features/leave-of-absence/lib/word-export.ts`:

1. **The trailing-paragraph 2pt pin was nested inside `if (typedOthers)`.**
   Bug: a long REMARKS entry spilled the template's invisible final paragraph
   onto a blank page 2 and the guard never fired. Moved to top level so it runs
   on **every** export.
2. **REASONS / REMARKS cell: `vAlign="center"` → `"top"`.** Its cell is a
   `w:vMerge w:val="restart"` spanning the three rows of the remarks box
   (517 + 750 + 765 = 2032 twips ≈ 135px). Centred, the text floated mid-box
   with dead space above — that IS the "too much space at the top" the user
   pointed at. `REMARKS_PARA_ID = "335E2876"`.
3. **Adaptive shrink for long entries** (`REMARKS_STEPS`): >300 / >700 / >1200
   / >1600 chars → 11 / 10 / 9 / 8pt with leading 220 / 200 / 180 / 160.
   Capacity scales ~1/f² with the point size, so 10pt ≈1.7× the 12pt capacity.

**Measured with Word COM (`ComputeStatistics(2)`):** 486 / 972 / 1620 chars →
**1 page** (972 was 2 pages before). 2430 chars → still 2 pages (~380 words;
no usable size fits that).

**Lessons:**
- **Check where a "fits on one page" guard is nested.** The LOA fix existed but
  sat inside the wrong conditional, so it silently never ran for the common
  case. Same class of bug could hide in OB/COS/OT — worth auditing.
- When a cell is a `w:vMerge`, `vAlign` applies to the **merged** box, not the
  single row the text sits in. Centre looks fine short and wastes space long.
- Verify page counts with Word COM, not by eyeballing XML.

## Login inputs: dropped the focus glow (same de-AI pass)

**User:** "this text field selected it looks like vibe coded" (pointing at the
navy halo on the focused ID-number input).

- `LoginForm.tsx` `INPUT_OK` / `INPUT_BAD` were using `focus:ring-4
  focus:ring-ring/15` — an 8px navy halo at 15% opacity. **The login was the
  only place in the app using `ring-4`**, every shadcn/ui input/dialog/select
  uses `ring-1` or `ring-2`. Changed to `focus:ring-1 focus:ring-ring/25`
  (2px at 25%, plus the existing `focus:border-ring`).
- **House rule (de-AI):** never use `ring-4` on form inputs. `ring-1` or
  `ring-2` max, at 20–30% opacity. Big diffuse rings read as AI chrome.
